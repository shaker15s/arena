## 1. تقسيم النطاق (Scoping — المحسوم قبل أول سطر)

### 🥚 MVP (نسخة الإطلاق الأول — يناسب فرعًا واحدًا حقيقيًا)
مصادقة OTP · معالج البداية · الفروع/اللجان/الكورسات/الباتشات · الانضمام والانتظار · الجلسات + **QR دوّار** + كود يدوي · الحضور 4 حالات · تقرير الجلسة · الأعذار · دفتر النقاط بالقواعد الافتراضية · المستويات · الستريك الأسبوعي + مُجمّد · شاشة اليوم والرحلة والمحفظة · إشعارات الجلسات · عربي/إنجليزي · دارك مود.
**بدونه لا إطلاق.**

### 🚀 V1 (أسبوعان بعد MVP)
الدوري الأسبوعي بالكامل + النجوم الصاعدة · الشارات الـ 12 + استوديو الشارات · الشهادات والتحقق العام والمشاركة PNG/PDF · المراسلات الجماعية · التحليلات للمدرب والمشرف · قواعد اللعبة S49 كاملة مع معاينة الأثر · سجل العمليات.

### 🌟 V2 (لاحقًا — بقرار بيانات)
روابط مواد خارجية داخل الكورس (بدون مشغل) · فُرق المجموعات (House Points) · تحديات أسبوعية (Quests) · وضع الكشك Kiosk للباب · ويدجت الستريك للشاشة الرئيسية · تكامل Web Parity للوحة المشرف · Geofence للحضور · إنجليزية/فرنسية إضافية.

## 2. خارطة الطريق الزمنية (12 أسبوعًا إلى MVP، 16 إلى V1)

| المرحلة | المدة | المخرجات | بوابة العبور (Exit Criteria) |
|---|---|---|---|
| **P0 — التأسيس والتصميم** | أسبوع 1–2 | Figma: نظام التصميم كاملًا (ألوان/تايب/مكونات) + تصاميم الشاشات الأربع الكبرى (اليوم/الاستكشاف/الجلسة الحية/لوحة المشرف) + تصدير Tokens JSON | مراجعة تصميم معتمدة · Tokens تُستورد وتُبنى في الكود بدون تعديل يدوي |
| **P1 — الهيكل والنواة** | أسبوع 3–4 | مشروع مسار 3.0 الجديد: الملاحة، الثيمات الثلاثة، i18n بالتكافؤ الآلي، مكونات design الأساسية، Migrations + عقود RPC + Seeds فرع تجريبي | تطبيق أجوف يتنقل بكل الثيمات واللغتين · RPC contract tests خضراء |
| **P2 — قلب الطالب** | أسبوع 5–7 | OTP · المعالج · اليوم · استكشف/تفاصيل/انضمام · رحلتي + خريطة الرحلة · سجل الحضور | طالب تجريبي ينضم لباتش ويشاهد رحلته — بدون أي واجهة Placeholder |
| **P3 — محرك الحضور** | أسبوع 8–9 | QR دوّار + كود يدوي + الجلسة الحية Realtime + الرصد اليدوي + الإغلاق والمحاسبة + الأعذار | فلو F3/F4/F5 يعمل E2E مع محاكاة غش (رمز قديم/تكرار) تفشل جميعها |
| **P4 — الجيميفيكيشن** | أسبوع 10–11 | دفتر النقاط + المستويات + محرك الستريك والمجمدات + المحفظة + لهيب الحالتين | سيناريو أسبوع كامل (محاكاة زمنية) → كل حالات الستريك الأربع صحيحة |
| **P5 — المدرب والمشرف** | أسبوع 12–13 | تقارير الجلسات · صندوق الأعذار · لوحة المشرف + قواعد اللعبة + المستخدمين + الأدوار | المشرف ينشئ كورسًا كاملًا من المعالج وحده بدون مساعدة |
| **P6 — الشهادات والبث** | أسبوع 14 | الإصدار + التحقق العام + المشاركة + المراسلات | شهادة حقيقية تتحقق منها متصفح غريب عبر الرابط العميق |
| **P7 — التلميع والإطلاق** | أسبوع 15–16 | كتالوج الحركات كاملًا · Skeleton/Shimmer · تخفيض الأحجام · اختبارات E2E · CI أخضر · نسخة Preview على أجهزة حقيقية 5 أيام | كل بوصلة الوثيقة 5 مرت · إطلاق V1 |

> **P7 ليس «إن بقي وقت» — هو مرحلة مسمّاة بخانتها.** التلميع البصري يأتي بعد عمل الفلوهات، لا قبله.

## 3. تعريف الاكتمال (Definition of Done) — لكل ميزة

**الميزة لا تُدمج إلا إذا:**
1. ✅ التصميم مطابق لملف Figma المعتمد بتوكنز `design/` فقط (لا قيم حرفية).
2. ✅ عربي/إنجليزي متكافئان 100% والاتجاه RTL صحيح — فاحص CI أخضر.
3. ✅ الحالات الست موصوفة ومبرمجة (وثيقة 03 §5): Loading/Empty/Error/Offline/Permission/Success.
4. ✅ كل منح نقاط/شارات عبر RPC بـ Idempotency — اختبار ضغط مكرر يمر.
5. ✅ الحركات من `design/motion` presets وتحترم Reduced Motion.
6. ✅ الهابتكس حسب المصفوفة · الأصوات مطفأة افتراضيًا.
7. ✅ 60fps على جهاز اختبار متوسط (Galaxy A52) — لقطة Perf Monitor مرفقة بالـ PR.
8. ✅ اختبار وحدات للمنطق + ملحق بعقد RPC إن وُجد.
9. ✅ Dark Mode وOLED مفحوصان بصريًا.
10. ✅ حدث تحليلات مُرسل بالاسم المتفق عليه.

## 4. خطة الجودة والاختبار (QA Blueprint)

### 4.1 الهرم
```
        E2E Maestro (السيناريو الذهبي كاملًا)
       ────────────────────────────────
      اختبارات تكامل RPC Contract (كل دالة = happy + 3 edge)
     ──────────────────────────────────────────
    وحدات: قواعد النقاط، آلة الاستريك، مستويات، تنسيقات i18n،
    صحة التوكنز، مصفوفة الصلاحيات (Role × Route)
   ──────────────────────────────────────────────
   ثوابت البوت: lint types صارم + فاحص التوكنز + فاحص التكافؤ
```

### 4.2 مصفوفة الأجهزة والشاشات
جهاز ضعيف (A14) · متوسط (A52) · حديث (S24 / iPhone 15) · تابلت أندرويد · شاشة بإشعارة Notch · خط نظام 130%.

### 4.3 ميزانيات الأداء (محسومة)
| المقياس | الميزانية |
|---|---|
| إقلاع دافئ حتى شاشة اليوم | ≤ 1.8 ثانية |
| إقلاع بارد | ≤ 3 ثواني |
| فريم كل الشاشات | 60 ثابت (120 حيث الشاشة تدعم) |
| حجم APK | ≤ 45MB |
| ذاكرة على الجلسة العادية | ≤ 180MB |
| Lottie الواحد | ≤ 1MB |

### 4.4 CI/CD
- كل PR: types + lint + unit + contract + parity + bundle size check.
- `develop` → EAS Preview لكل PR · `web` → Production.
- Migrations: تُراجع يدويًا وتُطبَّق على staging قبل الإنتاج — لا SQL مباشر على الإنتاج أبدًا.
- إصدار أسبوعي داخلي (TestFlight/APK) حتى لو صغير — الإيقاع يصنع الثقة.

## 6. مقياس «نجحنا» بعد 60 يومًا من الإطلاق
- ≥ 70% من كشوف الحضور تتم عبر التطبيق لا الورق.
- زمن إقفال الجلسة (تقرير شامل) < دقيقتين عند المدرب.
- ≥ 40% من الطلاب النشطين يحملون ستريك ≥ 3 أسابيع.
- صفر شكوى «شهادتي مش بتتحقق».
- تقييم المتجر ≥ 4.6.
